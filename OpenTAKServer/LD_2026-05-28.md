## 1. Purpose

This document elaborates the architecture from TLD-001 at component level. It describes the internal workings of the core components of OpenTAKServer: the EUD Handler, the Marti API, the OTS API, the message pipeline via RabbitMQ, the database layer, authentication and authorisation, and the video streaming integration.

Target audience: architects and senior engineers who need implementation details and interface contracts.

---

## 2. Scope

**In scope:**
- EUD Handler: TCP/SSL/UDP connection management and CoT forwarding
- Marti API: all sub-blueprints and their responsibilities
- OTS API: REST endpoints and authorisation model
- RabbitMQ exchanges and message flow
- Database model and ORM layer
- Authentication (Flask-Security-Too, LDAP, 2FA, certificates)
- APScheduler background tasks
- MediaMTX integration
- Plugin Manager

**Out of scope:**
- WebUI (OpenTAKServer-UI, separate project)
- TAK client implementations
- Federation (not yet implemented)

## 5. Detailed Design

### 5.1 EUD Handler

The EUD Handler manages persistent TCP connections from TAK clients. There are three transport layers:

| Server | Port | Protocol | Description |
|---|---|---|---|
| EudServer | 8088 | TCP (plaintext) | Unencrypted CoT connection |
| EudServerSSL | 8089 | TCP over TLS | Encrypted CoT connection with client certificate |
| EudServerUdp | 8087 | UDP | UDP broadcast of CoT messages |

**EUD Handler message flow:**
1. Client connects via TCP/SSL.
2. EudHandler / EudHandlerSSL receives raw CoT XML.
3. Message is parsed and published to the `cot_parser` RabbitMQ exchange.
4. `cot_parser` consumers store the message in the database and distribute it via the appropriate exchanges (`dms`, `chatrooms`, `groups`, `firehose`).
5. All subscribed clients receive the message via their own connection or via SocketIO.

### 5.2 Marti API

The Marti API implements the TAK server protocol and consists of the following sub-blueprints:

| Blueprint | Path | Function |
|---|---|---|
| `certificate_enrollment_api` | `/Marti/api/tls/*` | Issuing and enrolling client certificates |
| `citrap_api` | `/Marti/api/citrap/*` | CIViL Tracking and Reporting Assistance Protocol |
| `contacts_marti_api` | `/Marti/api/contacts/*` | Contact list of connected EUDs |
| `cot_marti_api` | `/Marti/api/cot/*` | Retrieving and sending CoT messages |
| `data_package_marti_api` | `/Marti/api/packages/*` | Upload/download of data packages (ZIP) |
| `device_profile_marti_api` | `/Marti/api/device/*` | Device profiles and settings |
| `group_marti_api` | `/Marti/api/groups/*` | Group/channel management |
| `mission_marti_api` | `/Marti/api/missions/*` | Mission API (Data Sync, Fire Area Survey) |

### 5.3 OTS API

The OTS API provides REST endpoints for the WebUI and external integrations. Contains endpoints for:
- User management (CRUD, roles, 2FA)
- EUD overview and status monitoring
- CoT data queries
- Video stream configuration (MediaMTX)
- Plugin management
- ADS-B and AIS data
- Meshtastic configuration
- System and log configuration

All OTS API endpoints fall under `/api/*` and are secured via Flask-Security-Too tokens/sessions.

### 5.4 RabbitMQ Message Pipeline

RabbitMQ forms the backbone of asynchronous message processing:

| Exchange | Type | Purpose |
|---|---|---|
| `cot_parser` | direct | Incoming CoT messages from EUD handlers to parsers |
| `dms` | direct | Direct messages between specific users |
| `chatrooms` | direct | Group chat messages |
| `missions` | topic | Mission feed updates (Data Sync) |
| `groups` | topic | Group/channel messages |
| `firehose` | fanout | All CoT data (for logging, monitoring) |
| `flask-socketio` | fanout | Forwarding to WebSocket clients (WebUI) |

CoT messages are retained by default for 86,400,000 ms (1 day) in the queue. The consumer prefetch is set to 2 messages.

### 5.5 Database and ORM

OpenTAKServer uses **PostgreSQL** via **SQLAlchemy** as ORM, with **Flask-Migrate** (Alembic) for schema management.

Key models:

| Model | Description |
|---|---|
| `User` | User accounts (Flask-Security-Too) |
| `Role` | Roles: `user`, `administrator` |
| `Group` | TAK groups/channels with bitpos mask |
| `EUD` | Registered TAK devices |
| `CoT` | Stored CoT messages (location, type, timestamp) |
| `DataPackage` | Uploaded data packages |
| `Mission` | Missions (Data Sync API) |
| `Icon` | Icon sets (downloaded from GitHub on first start) |
| `WebAuthn` | WebAuthn credentials for hardware 2FA |

Database connection: `postgresql+psycopg://ots:PASSWORD@127.0.0.1/ots`

### 5.6 Authentication and Authorisation

**Flask-Security-Too** handles the complete auth stack:

| Feature | Configuration |
|---|---|
| Username + password | Required; minimum 8 characters |
| Two-Factor Authentication | TOTP (authenticator app) + email (optional) |
| Client certificates | Via internal CA; used for SSL EUD connections |
| LDAP / Active Directory | Optional; `OTS_ENABLE_LDAP=True` |
| Email confirmation | Optional; `OTS_ENABLE_EMAIL=True` |
| CSRF protection | Flask-WTF CSRF protection on all forms |
| Session cookies | SameSite=Strict |

Roles:
- `user`: default role after registration; can connect devices, send messages
- `administrator`: full access including user management and server configuration

### 5.7 Certificate Authority

The internal CA (`certificate_authority.py`) generates:
- A root CA certificate (`OTS_CA_NAME`, default "OpenTAKServer-CA")
- Client certificates for EUD authentication during SSL connections
- Certificates are stored in `OTS_CA_FOLDER` (default `~/ots/ca`)
- Validity: 3650 days (10 years)

### 5.8 APScheduler — Background Tasks

| Job ID | Trigger | Function |
|---|---|---|
| `get_adsb_data` | Every minute | Fetch ADS-B aircraft data via external API |
| `ais` | Every minute | Fetch AIS shipping data via AISHub |
| `delete_video_recordings` | Every minute | Delete expired video recordings |
| `delete_old_data` | Every minute | Delete old CoT messages (configurable) |
| `purge_data` | Daily midnight | Large-scale data cleanup |

Jobs are stored in PostgreSQL via `SQLJobStore`.

### 5.9 MediaMTX Video Integration

MediaMTX is an external video server controlled via REST API on port 9997:
- OTS communicates with MediaMTX via `OTS_MEDIAMTX_API_ADDRESS`
- A shared token (`OTS_MEDIAMTX_TOKEN`) secures the API communication
- TAK clients can start/view video streams via RTSP/RTMP/HLS
- Video streaming is optional (`OTS_MEDIAMTX_ENABLE`)

### 5.10 Plugin Manager

The Plugin Manager loads Python packages with the prefix `ots-` or `ots_` as plugins:
- Plugins are actively loaded at server startup when `OTS_ENABLE_PLUGINS=True`
- Plugin repository: `https://repo.opentakserver.io/brian/prod/`
- Plugins can register their own blueprints, models and background tasks
- Mumble authentication and Meshtastic integration are available as optional modules

## 6. Interfaces

| Interface | Direction | Protocol | Description |
|---|---|---|---|
| EUD → OTS | Inbound | TCP :8088 | CoT XML (plaintext) |
| EUD → OTS | Inbound | TCP :8089 TLS | CoT XML (encrypted + client cert) |
| EUD → OTS | Inbound | UDP :8087 | CoT XML UDP broadcast |
| WebUI → OTS | Inbound | HTTPS :8443 | REST API + WebSocket |
| TAK clients → OTS | Inbound | HTTPS :8443 | Marti API |
| OTS → RabbitMQ | Internal | AMQP :5672 | Message distribution |
| OTS → PostgreSQL | Internal | TCP :5432 | ORM queries |
| OTS → MediaMTX | Outbound | HTTP :9997 | Video API |
| OTS → ADS-B API | Outbound | HTTPS | Aircraft data (airplanes.live) |
| OTS → AISHub | Outbound | HTTPS | Shipping data |

## 7. Configuration

| Parameter | Default | Description |
|---|---|---|
| `OTS_LISTENER_PORT` | 8081 | Flask/gevent listening port |
| `OTS_MARTI_HTTP_PORT` | 8080 | Marti HTTP port |
| `OTS_MARTI_HTTPS_PORT` | 8443 | Marti HTTPS port |
| `OTS_TCP_STREAMING_PORT` | 8088 | EUD TCP port |
| `OTS_SSL_STREAMING_PORT` | 8089 | EUD SSL port |
| `OTS_UDP_PORT` | 8087 | EUD UDP port |
| `OTS_RABBITMQ_SERVER_ADDRESS` | 127.0.0.1 | RabbitMQ host |
| `OTS_CA_PASSWORD` | atakatak | CA password (CHANGE in production!) |
| `OTS_DELETE_OLD_DATA_WEEKS` | 1 | CoT data retention period |
| `SQLALCHEMY_DATABASE_URI` | postgresql+psycopg://ots:...@127.0.0.1/ots | Database connection string |

Configuration is loaded from `~/ots/config.yml`. On first start this file is created from `DefaultConfig`.

## 8. Limitations and Constraints

- RabbitMQ, PostgreSQL and openssl must be installed externally before the server starts.
- MediaMTX is optional but required for video streaming functionality.
- Federation is not yet implemented; multi-server scenarios are not supported.
- The default CA password (`atakatak`) must be changed in production environments.
- gevent monkey-patching is applied at startup; this affects all Python threads in the process.
