## 1. Doel

Dit document werkt de architectuur uit TLD-001 verder uit op componentniveau. Het beschrijft de interne werking van de kerncomponenten van OpenTAKServer: de EUD Handler, de Marti API, de OTS API, de berichtenpijplijn via RabbitMQ, de databaselaag, authenticatie en autorisatie, en de videostreaming-integratie.

---

## 2. Scope

**In scope:** EUD Handler, Marti API, OTS API, RabbitMQ-exchanges, databasemodel, authenticatie (Flask-Security-Too, LDAP, 2FA), APScheduler, MediaMTX-integratie, Plugin Manager.

**Buiten scope:** WebUI (apart project), TAK-clientimplementaties, Federatie.

## 5. Gedetailleerd ontwerp

### 5.1 EUD Handler

| Server | Poort | Protocol | Beschrijving |
|---|---|---|---|
| EudServer | 8088 | TCP (plaintext) | Onbeveiligde CoT-verbinding |
| EudServerSSL | 8089 | TCP over TLS | Beveiligde CoT-verbinding met clientcertificaat |
| EudServerUdp | 8087 | UDP | UDP-broadcast van CoT-berichten |

Berichtenflow: Client verbindt → EudHandler ontvangt CoT XML → publiceert op `cot_parser` exchange → consumer slaat op in DB en distribueert via `dms`, `chatrooms`, `groups`, `firehose`.

### 5.2 Marti API Sub-blueprints

| Blueprint | Pad | Functie |
|---|---|---|
| `certificate_enrollment_api` | `/Marti/api/tls/*` | Uitgifte en inschrijving van clientcertificaten |
| `citrap_api` | `/Marti/api/citrap/*` | CIViL Tracking and Reporting |
| `contacts_marti_api` | `/Marti/api/contacts/*` | Contactlijst van verbonden EUDs |
| `cot_marti_api` | `/Marti/api/cot/*` | CoT berichten ophalen en versturen |
| `data_package_marti_api` | `/Marti/api/packages/*` | Upload/download van data packages |
| `device_profile_marti_api` | `/Marti/api/device/*` | Apparaatprofielen en -instellingen |
| `group_marti_api` | `/Marti/api/groups/*` | Groepen/channels beheer |
| `mission_marti_api` | `/Marti/api/missions/*` | Mission API (Data Sync, Fire Area Survey) |

### 5.3 OTS API

REST API voor de WebUI onder `/api/*`, beveiligd via Flask-Security-Too. Endpoints voor gebruikersbeheer, EUD-monitoring, CoT-queries, video (MediaMTX), plugins, ADS-B, AIS, Meshtastic en logging.

### 5.4 RabbitMQ Berichtenpijplijn

| Exchange | Type | Doel |
|---|---|---|
| `cot_parser` | direct | Inkomende CoT-berichten naar parsers |
| `dms` | direct | Directe berichten tussen gebruikers |
| `chatrooms` | direct | Groepschatberichten |
| `missions` | topic | Mission feed updates (Data Sync) |
| `groups` | topic | Groep/channel-berichten |
| `firehose` | fanout | Alle CoT-data (logging, monitoring) |
| `flask-socketio` | fanout | Doorsturen naar WebSocket clients (WebUI) |

CoT-berichten worden 86.400.000 ms (1 dag) bewaard. Consumer prefetch: 2 berichten.

### 5.5 Database en ORM

PostgreSQL via SQLAlchemy, Flask-Migrate voor schemabeheer.

| Model | Beschrijving |
|---|---|
| `User` | Gebruikersaccounts (Flask-Security-Too) |
| `Role` | Rollen: `user`, `administrator` |
| `Group` | TAK-groups/channels met bitpos-masker |
| `EUD` | Geregistreerde TAK-apparaten |
| `CoT` | Opgeslagen CoT-berichten |
| `DataPackage` | Geüploade data packages |
| `Mission` | Missies (Data Sync API) |
| `Icon` | Iconsets |
| `WebAuthn` | Hardware 2FA credentials |

### 5.6 Authenticatie en Autorisatie

| Feature | Configuratie |
|---|---|
| Gebruikersnaam + wachtwoord | Verplicht; minimaal 8 tekens |
| Two-Factor Authentication | TOTP + e-mail (optioneel) |
| Clientcertificaten | Via interne CA |
| LDAP / Active Directory | `OTS_ENABLE_LDAP=True` |
| E-mailbevestiging | `OTS_ENABLE_EMAIL=True` |
| Sessiecookies | SameSite=Strict |

Rollen: `user` (standaard), `administrator` (volledige toegang).

### 5.7 Certificate Authority

Root CA (`OTS_CA_NAME` = "OpenTAKServer-CA"), clientcertificaten in `OTS_CA_FOLDER` (~`/ots/ca`), geldigheid 3650 dagen.

### 5.8 APScheduler Achtergrondtaken

| Job ID | Trigger | Functie |
|---|---|---|
| `get_adsb_data` | Elke minuut | ADS-B vliegtuigdata ophalen |
| `ais` | Elke minuut | AIS scheepvaartdata |
| `delete_video_recordings` | Elke minuut | Verlopen video-opnames verwijderen |
| `delete_old_data` | Elke minuut | Oude CoT-berichten verwijderen |
| `purge_data` | Dagelijks middernacht | Grootschalige data-opruiming |

Jobs opgeslagen in PostgreSQL via `SQLJobStore`.

### 5.9 MediaMTX Video Integratie

REST API op poort 9997, token-gebaseerde authenticatie (`OTS_MEDIAMTX_TOKEN`). RTSP/RTMP/HLS streaming. Optioneel via `OTS_MEDIAMTX_ENABLE`.

### 5.10 Plugin Manager

Laadt packages met prefix `ots-` of `ots_`. Plugin repository: `https://repo.opentakserver.io/brian/prod/`. Actief als `OTS_ENABLE_PLUGINS=True`.

## 6. Interfaces

| Interface | Richting | Protocol | Beschrijving |
|---|---|---|---|
| EUD → OTS | Inkomend | TCP :8088 | CoT XML (plaintext) |
| EUD → OTS | Inkomend | TCP :8089 TLS | CoT XML (versleuteld + clientcert) |
| EUD → OTS | Inkomend | UDP :8087 | CoT XML UDP broadcast |
| WebUI → OTS | Inkomend | HTTPS :8443 | REST API + WebSocket |
| TAK clients → OTS | Inkomend | HTTPS :8443 | Marti API |
| OTS → RabbitMQ | Intern | AMQP :5672 | Berichtdistributie |
| OTS → PostgreSQL | Intern | TCP :5432 | ORM queries |
| OTS → MediaMTX | Uitgaand | HTTP :9997 | Video API |

| `OTS_CA_PASSWORD` | atakatak | CA-wachtwoord (WIJZIGEN in productie!) |

---

## 8. Beperkingen

- RabbitMQ, PostgreSQL en openssl moeten voor serverstart geïnstalleerd zijn.
- Federatie is niet geïmplementeerd.
- Standaard CA-wachtwoord (`atakatak`) moet verplicht gewijzigd worden.
- gevent monkey-patching beïnvloedt alle Python-threads.

---

## 9. Testoverwegingen

- EUD Handler: TCP + SSL connectietest met ATAK.
- Marti API: certificaatinschrijving end-to-end.
- RabbitMQ: alle exchanges correct aangemaakt bij startup.
- Auth: 2FA-flow (TOTP + e-mail), LDAP in testomgeving.
- APScheduler: jobs worden uitgevoerd en data opgeruimd.
- Plugin Manager: laden en activeren van minimaal één plugin.
