## 1. Doel

Dit document beschrijft het hoogover technisch ontwerp van **OpenTAKServer (OTS)**, een open-source TAK-server (Team Awareness Kit) compatibel met ATAK, iTAK, WinTAK, TAKAware, TAKX, CloudTAK en PyTAK. Het document is bestemd voor architecten, programmamanagers en technische leads die inzicht willen in de opzet, keuzes en samenhang van het systeem.

OpenTAKServer heeft als doel: een eenvoudig te installeren, volledig functionele TAK-server die draait op zowel servers als single-board computers (bijv. Raspberry Pi).

---

## 2. Scope

**In scope:**
- Systeemarchitectuur van OpenTAKServer
- Communicatieprotocollen tussen TAK-clients en de server
- Kerncomponenten: EUD Handler, Marti API, OTS API, berichtbroker, database, certificaatbeheer
- Authenticatie- en autorisatiemodel
- Video streaming integratie
- Plugin-architectuur

**Buiten scope:**
- Interne werking van TAK-clientapplicaties (ATAK, WinTAK, iTAK)
- Federatiekoppeling (gepland, nog niet geïmplementeerd)
- Installatie- en operationele handleidingen

## 5. Architectuuroverzicht

OpenTAKServer is een Python-applicatie gebouwd op het **Flask** web framework, met **gevent** voor asynchrone I/O. De server vormt de kern van een TAK-ecosysteem en verzorgt de communicatie tussen veldapparaten.

### 5.1 Kerncomponenten

| Component | Beschrijving |
|---|---|
| **EUD Handler** | Verwerkt TCP/SSL/UDP-verbindingen van TAK-clients. Ontvangt CoT-berichten en stuurt ze door via RabbitMQ. |
| **Marti API** | Implementeert het TAK Marti-protocol: certificaatinschrijving, contacten, CoT, data packages, groepsbeheer, Mission API. |
| **OTS API** | REST API voor de WebUI en externe integraties. |
| **SocketIO** | Realtime WebSocket-communicatie voor de live kaart in de WebUI. |
| **RabbitMQ** | Berichtbroker die CoT-berichten distribueert tussen componenten via exchanges en queues. |
| **PostgreSQL** | Relationele database voor persistente opslag (gebruikers, CoT-geschiedenis, missies, etc.). |
| **Certificate Authority** | Interne CA voor het aanmaken en beheren van clientcertificaten voor TLS-authenticatie. |
| **APScheduler** | Achtergrondtaken: ADS-B data ophalen, AIS data, data opruimen, video-opnames verwijderen. |
| **MediaMTX** | Externe videoserver voor RTSP/RTMP/HLS streaming, aangestuurd via de OTS API. |
| **Plugin Manager** | Laadt en beheert optionele plugins die de kernfunctionaliteit uitbreiden. |

## 6. Ontwerpbeslissingen

| Beslissing | Motivatie | Alternatief overwogen |
|---|---|---|
| Python + Flask | Breed ecosysteem, TAK-community ondersteuning | FastAPI, Django |
| gevent voor async I/O | Compatibel met Flask, schaalt voor veel TCP-verbindingen | asyncio / uvicorn |
| RabbitMQ als berichtbroker | Betrouwbare exchanges per berichttype | Redis Pub/Sub |
| PostgreSQL | Robuust, ondersteunt complexe CoT-queries | SQLite, MySQL |
| Interne Certificate Authority | Geen externe afhankelijkheid voor clientcertificaten | Let's Encrypt |
| MediaMTX voor video | Open-source, alle gangbare streamingprotocollen | Wowza, Ant Media |
| nginx als reverse proxy | Productie-grade TLS, load balancing | Caddy, Apache |
