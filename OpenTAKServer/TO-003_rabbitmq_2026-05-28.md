## 1. Purpose

This document describes the installation and configuration of RabbitMQ as the message broker for OpenTAKServer (OTS). RabbitMQ handles asynchronous communication between the CoT parser, WebSocket clients (Flask-SocketIO), mission data, and group messages. Correct creation of exchanges with their types and TTL settings is essential for reliable operation of the messaging system.

## 4. Prerequisites

- [ ] Ubuntu 22.04 or 24.04 LTS installed and updated
- [ ] Root or sudo access available
- [ ] Internet access for apt packages (or offline mirror available)
- [ ] Port 5672 (AMQP) available (not in use by another process)
- [ ] Port 15672 (Management UI) available
- [ ] Minimum 512 MB free RAM for RabbitMQ daemon
- [ ] OpenTAKServer installed (`OTS_RABBITMQ_*` config variables available)
- [ ] `curl` available: `which curl`

## 5. Procedure

### Step 1 — Add Erlang and RabbitMQ repositories

**Action:** Add official RabbitMQ apt repository.

```bash
# Install required tools
sudo apt-get install -y curl gnupg apt-transport-https

# Add Erlang repository
curl -1sLf 'https://dl.cloudsmith.io/public/rabbitmq/rabbitmq-erlang/setup.deb.sh' | sudo -E bash

# Add RabbitMQ repository
curl -1sLf 'https://dl.cloudsmith.io/public/rabbitmq/rabbitmq-server/setup.deb.sh' | sudo -E bash

sudo apt-get update -y
```

**Expected Result:** Repository added, packages available.

**Verification:** `apt-cache policy rabbitmq-server` shows version from official channel.

---

### Step 2 — Install Erlang and RabbitMQ

**Action:** Install Erlang runtime and RabbitMQ server.

```bash
sudo apt-get install -y erlang-base erlang-asn1 erlang-crypto erlang-eldap \
  erlang-ftp erlang-inets erlang-mnesia erlang-os-mon erlang-parsetools \
  erlang-public-key erlang-runtime-tools erlang-snmp erlang-ssl \
  erlang-syntax-tools erlang-tftp erlang-tools erlang-xmerl rabbitmq-server
```

**Expected Result:** Package installed, service started.

**Verification:** `systemctl status rabbitmq-server` shows `active (running)`.

---

### Step 3 — Enable and start the RabbitMQ service

**Action:** Enable autostart and start the service.

```bash
sudo systemctl enable rabbitmq-server && sudo systemctl start rabbitmq-server
```

**Expected Result:** Service active and configured for autostart.

**Verification:** `sudo rabbitmqctl status` shows server information.

---

### Step 4 — Enable Management plugin

**Action:** Activate the RabbitMQ Management UI plugin.

```bash
sudo rabbitmq-plugins enable rabbitmq_management
```

**Expected Result:** Plugin activated, port 15672 listening.

**Verification:** `curl -s http://localhost:15672/` returns HTML page.

---

### Step 5 — Create OTS RabbitMQ user

**Action:** Create a dedicated RabbitMQ user for OTS.

```bash
sudo rabbitmqctl add_user ots REPLACE_WITH_STRONG_PASSWORD
sudo rabbitmqctl set_user_tags ots administrator
sudo rabbitmqctl set_permissions -p / ots ".*" ".*" ".*"
```

**Expected Result:** User created with full permissions on default vhost.

**Verification:** `sudo rabbitmqctl list_users` shows `ots` with tag `[administrator]`.

> **Note:** Replace `REPLACE_WITH_STRONG_PASSWORD` with a secure password. Record it for OTS configuration.

---

### Step 6 — Remove default guest user

**Action:** Delete the insecure default guest user.

```bash
sudo rabbitmqctl delete_user guest
```

**Expected Result:** Guest account removed.

**Verification:** `sudo rabbitmqctl list_users` no longer shows `guest`.

---

### Step 7 — Create exchanges

**Action:** Create all required OTS exchanges via the Management API.

```bash
#!/bin/bash
RABBITMQ_USER="ots"
RABBITMQ_PASS="REPLACE_WITH_STRONG_PASSWORD"
MGMT_URL="http://localhost:15672/api"

declare -A EXCHANGES
EXCHANGES=(
  ["dms"]="direct"
  ["cot_parser"]="direct"
  ["chatrooms"]="direct"
  ["missions"]="topic"
  ["groups"]="topic"
  ["firehose"]="fanout"
  ["flask-socketio"]="fanout"
)

for EXCHANGE in "${!EXCHANGES[@]}"; do
  TYPE="${EXCHANGES[$EXCHANGE]}"
  echo "Creating exchange: $EXCHANGE (type: $TYPE)"
  curl -s -u "$RABBITMQ_USER:$RABBITMQ_PASS" \
    -X PUT \
    -H "Content-Type: application/json" \
    -d "{\"type\": \"$TYPE\", \"durable\": true, \"auto_delete\": false, \"arguments\": {\"x-message-ttl\": 86400000}}" \
    "$MGMT_URL/exchanges/%2F/$EXCHANGE"
  echo ""
done
echo "All exchanges created."
```

**Expected Result:** All 7 exchanges created.

**Verification:** Management UI at `http://localhost:15672/#/exchanges` shows all exchanges.

---

### Step 8 — Verify TTL on exchanges

**Action:** Confirm TTL setting (86,400,000 ms = 24 hours) on exchanges.

```bash
curl -s -u ots:PASSWORD http://localhost:15672/api/exchanges/%2F/dms | python3 -m json.tool
```

**Expected Result:** JSON shows `"x-message-ttl": 86400000` in arguments.

**Verification:** All 7 exchanges show the correct TTL argument.

---

### Step 9 — Update OTS configuration

**Action:** Set RabbitMQ connection details in OTS config.

```bash
sudo nano /etc/opentakserver/config.yml
```

Relevant fields in `/etc/opentakserver/config.yml`:

```yaml
OTS_RABBITMQ_SERVER_ADDRESS: "127.0.0.1"
OTS_RABBITMQ_SERVER_PORT: 5672
OTS_RABBITMQ_SERVER_USERNAME: "ots"
OTS_RABBITMQ_SERVER_PASSWORD: "REPLACE_WITH_STRONG_PASSWORD"
```

**Expected Result:** Configuration file updated.

**Verification:** `sudo cat /etc/opentakserver/config.yml | grep -i rabbit`

---

### Step 10 — Restart OTS and verify connection

**Action:** Restart OTS and check the RabbitMQ connection in the logs.

```bash
sudo systemctl restart ots && sudo journalctl -u ots -n 50 --no-pager
```

**Expected Result:** No RabbitMQ connection errors in the log.

**Verification:** Log shows `Connected to RabbitMQ` or equivalent confirmation.

## 7. Rollback Procedure

1. Stop OTS to prevent further connection attempts:
   ```bash
   sudo systemctl stop ots
   ```
2. Remove created exchanges via Management API or UI.
3. Remove OTS user if needed:
   ```bash
   sudo rabbitmqctl delete_user ots
   ```
4. Stop RabbitMQ if full removal is desired:
   ```bash
   sudo systemctl stop rabbitmq-server
   sudo systemctl disable rabbitmq-server
   sudo apt-get remove --purge rabbitmq-server erlang-* -y
   ```
5. Restore OTS configuration to previous state (remove RabbitMQ connection details).

## 8. Known Issues and Workarounds

| Issue | Circumstance | Workaround |
|---|---|---|
| `AMQPLAIN login refused` error in OTS | Incorrect password or user not created | Check `rabbitmqctl list_users`; reset password with `rabbitmqctl change_password ots NEW_PASSWORD` |
| Management UI not accessible | Plugin not enabled or firewall blocking | `rabbitmq-plugins enable rabbitmq_management`; check ufw for port 15672 |
| RabbitMQ fails to start after reboot | Erlang version incompatibility | Check `erl -version`; ensure compatible Erlang version |
| High memory usage | Many messages in queue without consumers | Set memory alarm: `rabbitmqctl set_vm_memory_high_watermark 0.4` |
| Exchange already exists on re-run | Idempotency: existing exchange with different properties | Delete exchange via UI or API first, then recreate |
| Messages lost after restart | Exchanges not durable | Ensure all exchanges are created with `"durable": true` |
