## 1. Purpose

This document describes the configuration of the internal Certificate Authority (CA) of OpenTAKServer. The OTS CA is responsible for issuing client certificates to TAK clients (ATAK, WinTAK, iTAK) for mutual TLS authentication (mTLS). This document covers changing the default CA password, initialising the CA on first server start, client certificate enrolment via the Marti API, and exporting to `.p12` format for use in ATAK.

## 5. Procedure

### Step 1 — Change the default CA password

**Action:** Update the default CA password in the OTS configuration before first start.

```bash
sudo nano /etc/opentakserver/config.yml
```

Set the following field to a strong password:

```yaml
OTS_CA_PASSWORD: "REPLACE_WITH_STRONG_CA_PASSWORD"
```

**Expected Result:** CA password updated in config.

**Verification:** `sudo cat /etc/opentakserver/config.yml | grep OTS_CA_PASSWORD`

---

### Step 2 — Initialise the CA on first start

**Action:** Start OpenTAKServer. On first launch, the CA is automatically initialised and root/intermediate certificates are generated.

```bash
sudo systemctl start ots
sudo journalctl -u ots -n 100 --no-pager | grep -i cert
```

**Expected Result:** CA certificates generated at `/etc/opentakserver/ssl/`.

**Verification:**
```bash
ls /etc/opentakserver/ssl/
```
Expected files: `ca.crt`, `ca.key`, `server.crt`, `server.key`.

---

### Step 3 — Enrol a client certificate via the Marti API

**Action:** Send a certificate signing request (CSR) from the TAK client to the Marti enrolment endpoint.

In ATAK: *Settings → Network → Server Connections → Add Server → enter server address → tap Enrol.*

The client automatically sends a CSR to:
```
https://<server>:8443/Marti/api/tls/config
https://<server>:8443/Marti/api/tls/signClient/v2
```

**Expected Result:** OTS signs the CSR and returns a signed client certificate.

**Verification:** OTS WebUI → *Certificates* shows the new client certificate with status `VALID`.

---

### Step 4 — Export certificate to .p12 for manual import

**Action:** If automatic enrolment is not available, export the signed certificate as a `.p12` bundle.

```bash
# On the server — find the client cert
ls /etc/opentakserver/ssl/certs/

# Export to .p12
openssl pkcs12 -export \
  -in /etc/opentakserver/ssl/certs/<callsign>.crt \
  -inkey /etc/opentakserver/ssl/certs/<callsign>.key \
  -certfile /etc/opentakserver/ssl/ca.crt \
  -out /tmp/<callsign>.p12 \
  -passout pass:REPLACE_WITH_P12_PASSWORD
```

**Expected Result:** `.p12` file created, ready for import into ATAK.

**Verification:** File exists: `ls -lh /tmp/<callsign>.p12`

---

### Step 5 — Import .p12 into ATAK

**Action:** Transfer the `.p12` file to the Android device and import it.

1. Copy `.p12` to the device (via USB, ADB, or secure file transfer).
2. In ATAK: *Settings → Network → Manage Server Certificates → Import.*
3. Enter the `.p12` password when prompted.
4. Connect to the OTS server using SSL on port 8089.

**Expected Result:** ATAK connects to OTS with mutual TLS; device appears in WebUI → EUDs.

**Verification:** OTS WebUI shows the device as connected with a green status.

## 7. Rollback Procedure

1. Stop OTS: `sudo systemctl stop ots`
2. To regenerate the CA (destroys all existing client certs):
   ```bash
   sudo rm -rf /etc/opentakserver/ssl/
   sudo systemctl start ots  # CA will be regenerated on next start
   ```
3. Re-enrol all TAK clients after CA regeneration.
4. Restore the previous CA password in `config.yml` if needed.

> **Warning:** Regenerating the CA invalidates all previously issued client certificates. All clients must re-enrol.

## 8. Known Issues and Workarounds

| Issue | Circumstance | Workaround |
|---|---|---|
| ATAK shows "certificate not trusted" | OTS CA cert not imported into device trust store | Import `ca.crt` manually into Android trusted credentials |
| Enrolment fails with 401 | OTS not configured to allow enrolment | Check `OTS_ENABLE_CERTIFICATE_ENROLLMENT` in config.yml |
| `.p12` import rejected by ATAK | Wrong password or corrupted file | Re-export with a simple alphanumeric password; avoid special characters |
| CA not initialised after first start | Config error or missing directories | Check `journalctl -u ots` for errors; verify `/etc/opentakserver/ssl/` permissions |
| Expired client certificates | Long-running deployments | Re-enrol clients; set `OTS_CA_EXPIRATION_TIME` to a suitable value (default: 3650 days) |
