## 1. Purpose

This document describes the installation and configuration of MediaMTX as the video streaming server for OpenTAKServer. MediaMTX handles RTSP, RTMP, HLS, and WebRTC streaming of video feeds from ATAK (drones, body cameras) to other TAK clients and the OTS WebUI. OTS integrates with MediaMTX via an API token for stream authentication and management.

## 4. Prerequisites

- [ ] OpenTAKServer installed and running
- [ ] Ports 8554 (RTSP), 1935 (RTMP), 8888 (HLS), 8889 (WebRTC) available
- [ ] Root or sudo access available
- [ ] `curl` available for downloading MediaMTX binary
- [ ] OTS API token generated (from OTS WebUI → Settings → API Tokens)

## 5. Procedure

### Step 1 — Download and install MediaMTX

**Action:** Download the latest MediaMTX release and install it.

```bash
# Download latest release (adjust version as needed)
MEDIAMTX_VERSION="v1.9.3"
curl -L "https://github.com/bluenviron/mediamtx/releases/download/${MEDIAMTX_VERSION}/mediamtx_${MEDIAMTX_VERSION}_linux_amd64.tar.gz" \
  -o /tmp/mediamtx.tar.gz

# Extract
tar -xzf /tmp/mediamtx.tar.gz -C /tmp/

# Move binary and config to /opt
sudo mkdir -p /opt/mediamtx
sudo mv /tmp/mediamtx /opt/mediamtx/mediamtx
sudo mv /tmp/mediamtx.yml /opt/mediamtx/mediamtx.yml
sudo chmod +x /opt/mediamtx/mediamtx
```

**Expected Result:** MediaMTX binary present at `/opt/mediamtx/mediamtx`.

**Verification:** `/opt/mediamtx/mediamtx --version` shows the installed version.

---

### Step 2 — Configure MediaMTX for OTS integration

**Action:** Edit `/opt/mediamtx/mediamtx.yml` with the OTS API token and required settings.

Key configuration fields:

```yaml
# API settings — enable so OTS can manage streams
api: yes
apiAddress: 127.0.0.1:9997

# RTSP settings
rtspAddress: :8554
rtspEncryption: no

# RTMP settings
rtmpAddress: :1935

# HLS settings
hlsAddress: :8888

# WebRTC settings
webrtcAddress: :8889

# Authentication hook — OTS validates streams
authMethod: http
authHTTPAddress: http://127.0.0.1:8081/api/mediamtx/auth
```

**Expected Result:** Configuration file updated with correct values.

**Verification:** `grep -E "api|apiAddress|authMethod|authHTTP" /opt/mediamtx/mediamtx.yml`

---

### Step 3 — Update OTS configuration with MediaMTX API token

**Action:** Generate an API token in the OTS WebUI and add it to the OTS config.

1. In OTS WebUI: *Settings → API Tokens → Generate New Token*. Copy the token.
2. Edit OTS config:

```bash
sudo nano /etc/opentakserver/config.yml
```

Add:

```yaml
OTS_MEDIAMTX_SERVER_ADDRESS: "127.0.0.1"
OTS_MEDIAMTX_API_PORT: 9997
OTS_MEDIAMTX_TOKEN: "REPLACE_WITH_GENERATED_TOKEN"
```

**Expected Result:** OTS configured to connect to MediaMTX API.

**Verification:** `sudo cat /etc/opentakserver/config.yml | grep MEDIAMTX`

---

### Step 4 — Create MediaMTX systemd service

**Action:** Create a systemd service to run MediaMTX automatically.

```bash
sudo tee /etc/systemd/system/mediamtx.service > /dev/null <<EOF
[Unit]
Description=MediaMTX Video Streaming Server
After=network.target

[Service]
Type=simple
User=root
ExecStart=/opt/mediamtx/mediamtx /opt/mediamtx/mediamtx.yml
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable mediamtx
sudo systemctl start mediamtx
```

**Expected Result:** MediaMTX running as a system service.

**Verification:** `systemctl status mediamtx` shows `active (running)`.

---

### Step 5 — Open firewall ports for streaming

**Action:** Allow the streaming ports through the firewall.

```bash
sudo ufw allow 8554/tcp comment "MediaMTX RTSP"
sudo ufw allow 1935/tcp comment "MediaMTX RTMP"
sudo ufw allow 8888/tcp comment "MediaMTX HLS"
sudo ufw allow 8889/tcp comment "MediaMTX WebRTC"
sudo ufw reload
```

**Expected Result:** All streaming ports open.

**Verification:** `sudo ufw status` shows rules for 8554, 1935, 8888, 8889.

---

### Step 6 — Restart OTS and verify integration

**Action:** Restart OTS to load the MediaMTX configuration.

```bash
sudo systemctl restart ots
sudo journalctl -u ots -n 50 --no-pager | grep -i media
```

**Expected Result:** OTS connects to MediaMTX API without errors.

**Verification:** OTS WebUI → *Video* section shows MediaMTX integration active.

## 6. Verification and Acceptance Criteria

| Criterion | Verification Method | Acceptance Value |
|---|---|---|
| MediaMTX service active | `systemctl status mediamtx` | `active (running)` |
| MediaMTX API accessible | `curl http://127.0.0.1:9997/v3/config/global/get` | JSON config returned |
| RTSP port open | `sudo ufw status` | 8554/tcp `ALLOW` |
| HLS port open | `sudo ufw status` | 8888/tcp `ALLOW` |
| OTS MediaMTX config loaded | OTS startup log | No MediaMTX connection errors |
| Video stream published from ATAK | ATAK → Share Video → RTSP | Stream appears in OTS WebUI → Video |
| Stream viewable in WebUI | OTS WebUI → Video | Live video plays in browser |

## 7. Rollback Procedure

1. Stop OTS: `sudo systemctl stop ots`
2. Stop and disable MediaMTX:
   ```bash
   sudo systemctl stop mediamtx
   sudo systemctl disable mediamtx
   ```
3. Close streaming ports:
   ```bash
   sudo ufw delete allow 8554/tcp
   sudo ufw delete allow 1935/tcp
   sudo ufw delete allow 8888/tcp
   sudo ufw delete allow 8889/tcp
   sudo ufw reload
   ```
4. Remove MediaMTX config from `config.yml`.
5. Restart OTS: `sudo systemctl start ots`

## 8. Known Issues and Workarounds

| Issue | Circumstance | Workaround |
|---|---|---|
| Stream not appearing in OTS WebUI | API token mismatch | Regenerate token in OTS WebUI; update `OTS_MEDIAMTX_TOKEN` in config |
| RTSP stream drops intermittently | Network instability | Increase `readBufferCount` in `mediamtx.yml`; use wired network |
| HLS stream has high latency | HLS segment duration too long | Reduce `hlsSegmentDuration` in `mediamtx.yml` (e.g. `1s`) |
| WebRTC not working | STUN/TURN not configured | Add STUN server in `mediamtx.yml`: `webrtcICEServers: [stun:stun.l.google.com:19302]` |
| MediaMTX fails to start | Port already in use | Check `ss -tlnp \| grep -E "8554|1935|8888|8889"`; stop conflicting service |
